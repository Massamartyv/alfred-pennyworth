# Per-Mission Model Assignment – Atlas Phase 1

This document overrides the global Model Selection Protocol for the duration of Phase 1 of Atlas – the SOAP note generator build and pilot.

**Status:** Draft. Operator approval required at Direction gate before any Execution proceeds.

The principle: model selection follows the cost of being wrong. Clinical taste-led work gets Opus. Code generation and rule-based validation get Sonnet. High-volume lookups and batch transformations get Haiku. The cost of an Opus call to curate a clinical knowledge file is trivial against the cost of a hallucinated diagnosis code in a real visit note.

---

## Mission Segment Allocation

### Clinical knowledge curation

**Tasks:** Authoring `Knowledge Base/Clinical/` and `Knowledge Base/Coding/` files – orthopedic tests, chiropractic listings, technique-specific terminology, ICD-10 mapped set, CPT mapped set, Medicare compliance rules.

**Crew:** Researcher → Creator

**Model:** Opus

**Rationale:** This is the defensible knowledge layer. Every error here propagates into every note generated by the system. Taste, judgement and clinical reasoning are required. The volume is finite (curated once, refined periodically) so the marginal token cost is irrelevant against accuracy.

### FastMCP scaffold and EHR adapters

**Tasks:** Building the FastMCP service, adapter files per EHR, schema definitions, error handling, retry logic.

**Crew:** Creator

**Model:** Sonnet

**Rationale:** Structured code generation with well-defined specifications. Sonnet is the workhorse for implementation. Fast iteration, strong code quality, cost-efficient for repeated work.

### SOAP note generation runtime

**Tasks:** The actual model call that converts ambient voice transcript into a structured SOAP note plus ICD-10 plus CPT plus plan.

**Crew:** Creator

**Model:** Sonnet for v1; benchmark Opus and Haiku at v1.1 with quality and latency comparison

**Rationale:** This is the user-facing per-visit inference, so the cost-quality balance is load-bearing. Sonnet is the starting point; the v1.1 benchmark determines whether Opus accuracy justifies the cost premium and whether Haiku speed justifies the quality reduction.

### Code validation pass

**Tasks:** Validating generated ICD-10 and CPT against curated sets, checking combination validity against CMS rules.

**Crew:** Reviewer:Scrutiny

**Model:** Sonnet

**Rationale:** Rule-based validation with structured inputs and outputs. Sonnet handles this comfortably. Haiku could work for individual code lookups but Sonnet handles the combination validation more reliably.

### Clinical read-through review

**Tasks:** Reading the generated note as a clinician would – is the technique terminology correct, does the plan match the technique, does it read like a competent chiropractor wrote it.

**Crew:** Reviewer:Behavioural

**Model:** Opus

**Rationale:** Clinical judgement equivalent to a senior chiropractor reading the note. This is the second line of defence against hallucination. Opus accuracy is non-negotiable.

### Batch ICD lookups

**Tasks:** Pre-computing the chiropractic ICD-10 set with full metadata, validating individual codes against CMS reference, building lookup indices.

**Crew:** Researcher

**Model:** Haiku

**Rationale:** Volume work with simple inputs and outputs. Speed and cost matter; depth does not.

### HIPAA audit log review

**Tasks:** Reviewing audit logs for anomalies, redaction integrity, access pattern analysis.

**Crew:** Reviewer:Scrutiny

**Model:** Sonnet

**Rationale:** Pattern matching on structured log data. Sonnet is well-suited; Opus is overkill.

### Discovery brief authoring (Arlando outreach)

**Tasks:** Drafting structured outreach to Arlando Parker Jr. to extract clinical context, EHR, technique, pilot constraints, terms appetite.

**Crew:** Creator

**Model:** Opus

**Rationale:** High-stakes, voice-led, irreversible. This sets the tone for the entire pilot relationship. Opus.

### Pilot communications (ongoing)

**Tasks:** Communications with Arlando during pilot – status updates, change requests, scope discussions.

**Crew:** Creator

**Model:** Opus

**Rationale:** Relationship management at the clinical advisor tier. Voice and judgement matter; volume is low.

### Internal Strategy and Finance work

**Tasks:** Competitive analysis, market research synthesis, financial modelling, projection drafting.

**Crew:** Researcher → Creator

**Model:** Sonnet for the body of work; Opus for the final synthesis and decision memo

**Rationale:** Most of this is research synthesis and structured analysis – Sonnet's strength. The decision memos that feed into Direction gates earn Opus.

### Brand and identity work (post art-direction trigger)

**Tasks:** Atlas brand identity build – naming, visual system, voice documentation.

**Crew:** Creator

**Model:** Opus

**Rationale:** Pure taste work. The brand identity governs every customer-facing surface. Opus.

## Review Cadence

This assignment is reviewed at:

- Phase 1 milestone boundary (post-MVP)
- Any time a model family ships a meaningfully new generation (Opus 5, Sonnet 5)
- Any time per-note inference cost exceeds the modelled unit economics budget
- Any time accuracy benchmarks shift against the validation contract

Modifications follow the same Direction-gate procedure as the validation contract.
